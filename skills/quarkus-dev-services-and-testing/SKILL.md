# Quarkus Dev Services and Testing

Check the project's Quarkus version first. Framework-neutral Testcontainers usage belongs to the `java-testcontainers` skill; this skill covers only Quarkus-specific features.

## Dev Services

In dev and test modes Quarkus starts containers (PostgreSQL, MySQL, Kafka, Redis, Keycloak, ...) automatically when the related extension is present and no connection is configured (Docker or Podman required).

```properties
quarkus.devservices.enabled=true                      # global switch
%dev.quarkus.datasource.devservices.image-name=postgres:17
quarkus.datasource.devservices.reuse=true             # reuse container across restarts
quarkus.datasource.devservices.port=5432              # fixed port (optional)
quarkus.kafka.devservices.shared=true                 # share between apps in dev mode
```

Disable one with `quarkus.<ext>.devservices.enabled=false`; configuring a URL/host explicitly also disables it. Dev UI (`/q/dev-ui`) lists running services.

## Tests

```java
@QuarkusTest
class GreetingResourceTest {
    @Test
    void hello() {
        given().when().get("/hello").then().statusCode(200).body(is("Hello"));
    }
}
```

Dependencies: `quarkus-junit5` (named `quarkus-junit` in newer versions) and `io.rest-assured:rest-assured`, test scope.

- Inject beans in tests with `@Inject`; mock CDI beans with `@InjectMock` (`quarkus-junit5-mockito`).
- Security: `@TestSecurity(user="alice", roles="admin")`.
- Profiles: `@TestProfile(MyProfile.class)` with `QuarkusTestProfile#getConfigOverrides()`; restarts the app, so use sparingly.
- Transactions: `@TestTransaction` rolls back after the test.
- `@QuarkusIntegrationTest` runs against the packaged artifact (jar, native binary or container); you cannot inject beans there, only call it over HTTP.

## Test resources

```java
public class WireMockResource implements QuarkusTestResourceLifecycleManager {
    public Map<String,String> start() { /* start, return config overrides */ return Map.of(); }
    public void stop() { }
}

@QuarkusTest
@QuarkusTestResource(WireMockResource.class)
class MyTest { }
```

Note `@QuarkusTestResource` applies globally to all tests unless `restrictToAnnotatedClass = true`. Prefer `@WithTestResource` where available in your version. Prefer Dev Services over custom resources when an extension supports it.

## Running

```bash
./mvnw test                 # unit/@QuarkusTest
./mvnw verify               # also runs *IT via maven-failsafe-plugin
```

Gotcha: `*IT` classes (`@QuarkusIntegrationTest`) are run by Failsafe in the `verify` phase, and need the `quarkus-maven-plugin` `build` goal and the failsafe config (with `java.util.logging.manager` and `maven.home` system properties) generated by the project template. `./mvnw test` silently skips them. Add `-Dnative` to run them against the native binary.

Continuous testing: run `./mvnw quarkus:dev` and press `r` to toggle; tests re-run on code changes (`quarkus.test.continuous-testing=enabled|paused|disabled`).

## Checklist

- Use Dev Services before writing a custom resource.
- Keep `@QuarkusTest` classes sharing the same profile/resources to avoid restarts.
- Do not hard-code ports; RestAssured uses `quarkus.http.test-port` automatically.
